# Pathfinder Waypoint V2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a production-ready Pathfinder rebuild in `liannbielicki/pathfinder-waypoint-v2` that accepts a clean audience, generates and evaluates recommendations, persists every stage, produces an LCM handoff, and proves capacity for 200 Pros/day.

**Architecture:** A Next.js operator frontend runs on Vercel and proxies `/api/*` to a FastAPI service on Railway. Railway API and worker processes share Supabase/Postgres as durable truth; workers claim jobs with Postgres leases, call the existing n8n context flow, use one metered LLM gateway, select Pro-matched persona panels, checkpoint the loop, and stop at an idempotent LCM handoff.

**Tech Stack:** Python 3.14, uv, FastAPI, Pydantic 2, SQLAlchemy 2, Alembic, asyncpg, httpx, Anthropic SDK, pytest, Node.js 24 LTS, pnpm 11.4, Next.js with TypeScript, React, Vitest, Testing Library, Playwright, Postgres/Supabase, Railway, Vercel.

## Global Constraints

- Build in the empty repository: `https://github.com/liannbielicki/pathfinder-waypoint-v2`.
- Read `docs/specs/pathfinder-production-rebuild-design.md` before changing code.
- Create `FRONTEND.md`; its first content section must be the eight approved UI principles.
- Frontend deploys to Vercel; API and workers deploy to Railway.
- Supabase/Postgres is the sole durable application truth; local files are scratch only.
- Reuse the existing n8n/Snowflake flow; never add direct Snowflake credentials to the app.
- Supplied audience IDs are already SQL-suppressed; validate and preserve lineage, but do not duplicate DNC logic.
- Pathfinder never sends. Allison's LCM tool owns final copy, personalization, Iterable DNC failsafe, and delivery.
- Persona screen is fixed at three: two closest qualifying matches plus one related cross-family counterweight.
- Final persona check is fixed at five: three closest qualifying matches plus two related cross-family counterweights.
- Every counterweight must clear the same Pro-fit threshold; identity, contact data, and protected traits never affect matching.
- Every winner stores one or two typed leading indicators; Iterable outcome readback is not in launch scope.
- Propensity/AIPW causal estimation is not in launch scope.
- 200 Pros/day is a hard launch gate demonstrated by a production-shaped load run.
- Runtime variable names are descriptive and shorter than 20 characters.
- Railway owns all secrets. Vercel has one non-secret routing value, `API_BASE_URL`, because the frontend must know the Railway origin.
- No canned recommendation fallback, silent write failure, unbounded retry, or model-authored code execution.
- Use test-first implementation, one focused commit per task, and no unrelated legacy code copying.
- Execute every task in order without pausing for approval between tasks. If a production credential or external contract is unavailable, complete all safe fixture-backed and independent work, record the exact human action required, and continue.
- Stop cleanly after the final human-handoff task. Do not continue into cutover, sending, Iterable readback, or unplanned improvements.

CLAIM_SQL = text("""
WITH next_job AS (
  SELECT id FROM jobs
  WHERE status = 'queued' OR (status = 'running' AND lease_until < now())
  ORDER BY created_at
  FOR UPDATE SKIP LOCKED
  LIMIT 1
)
UPDATE jobs
SET status = 'running', worker_id = :worker_id,
    lease_until = now() + make_interval(secs => :lease_seconds),
    attempts = attempts + 1
WHERE id IN (SELECT id FROM next_job)
RETURNING *
""")

```python
class LLMGateway:
    def __init__(self, client: AsyncAnthropic, session: AsyncSession, pricing: Pricing):
        self.client = client
        self.session = session
        self.pricing = pricing

    async def complete(self, tier: Literal["fast", "deep"], prompt: str,
                       run_id: str, stage: str) -> LLMResult:
        model = self.pricing.model_for(tier)
        response = await retry_rate_limit(
            lambda: self.client.messages.create(
                model=model, max_tokens=1200,
                messages=[{"role": "user", "content": prompt}],
            ), attempts=3,
        )
        result = LLMResult.from_response(response, self.pricing)
        self.session.add(UsageRow.from_result(run_id, stage, result))
        await self.session.flush()
        return result
```

```python
def select_panel(pro: ProMatchInput, personas: list[Persona], size: Literal[3, 5]) -> PanelSelection:
    closest_count = 2 if size == 3 else 3
    counter_count = size - closest_count
    ranked = sorted(score_personas(pro, personas), key=lambda item: (-item.fit_score, item.persona_id))
    closest = ranked[:closest_count]
    used_families = {item.family for item in closest}
    counterweights = [
        item for item in ranked[closest_count:]
        if item.fit_score >= FIT_THRESHOLD and item.family not in used_families
    ][:counter_count]
    if len(counterweights) != counter_count:
        raise InsufficientPanelFit(size=size, available=len(closest) + len(counterweights))
    return PanelSelection(items=[*closest, *counterweights], fit_threshold=FIT_THRESHOLD)
```
