## 1. What it actually does

This unit is the **persona-scoring and idea-judging half of the action console loop**: it turns a generated idea into a churn-reduction estimate, decides whether that estimate may stop the run, ranks/suppresses ideas, and tells the generator what to try next.

- **`persona_response.py` (1009 loc)** — the adapter between the action-console domain and `SyntheticPersonaEvaluator`. `_build_candidate()` maps an audience+idea into a persona request: segment derived from the audience's first `cell` filter via `segment_code_to_persona_key` (persona_response.py:323-333); the "content" personas react to is a **scrubbed concept description**, not message copy — `_scrub_persona_content()` strips UUIDs, org counts, `cell=`/`plan=` fragments and rewrites "org"→"pro" (persona_response.py:254-273), and `_persona_strategy_content()` composes "Action concept for the pro: … Recommended channel/timing: …" (persona_response.py:276-309). `_map_result()` converts evaluator fraction units to percentage points once at the boundary (`_PP_SCALE = 100.0`, persona_response.py:245, 410-420) and maps outcomes fail-closed: transport/score errors → `status="failed"`, gate rejections → `"abstained"` with `reduction=None`; only `reaction_not_significant` abstentions keep a labeled, non-authoritative `screening_reduction_pp` (persona_response.py:456-487). `clears_goal()` is the stop-decision rule: learned calibration needs `reduction >= goal_pp AND ci_lower >= floor AND in_calibrated_range`; a `directional_prior` estimate clears on `direction_ci_lower > floor` alone, with the floor read live from `persona_gate.SIGNIFICANCE_FLOOR_PP` = 1.0pp (persona_response.py:136-180, persona_gate.py:48). `_build_evaluator_from_env()` wires either provider: **persona-cards** (Riley's cards + local reaction walk + frozen cards calibration + `ReactionSignificanceGate`, persona_response.py:626-674) or **sequence-react** (our Railway fork + frozen 2026-06-24 calibration + `CalibrationGate`, persona_response.py:676-730). `_validate_cards_direction()` blocks scoring if the cards calibration's sign is not negative, and explicitly **accepts** a `slope_sign_forced_negative` artifact as "the expected, current state" (persona_response.py:541-556). `settle_channel_by_scorer()` re-scores the winner on each alternate channel and switches only on a ≥0.25pp margin (persona_response.py:191-234). `PersonaResponseScorer` is the runner's entry point; `final_choice_panel()` runs the winner against a 10-persona panel for qualitative readouts (persona_response.py:911-1009).
- **`reaction_provider.py` (103 loc)** — a `Protocol` seam plus two classes (`SequenceReactionProvider`, `PersonaCardsReactionProvider`) that are byte-identical except for the `provider=` string they pass to `_build_evaluator_from_env`; `make_reaction_provider()` selects by env (reaction_provider.py:92-103). Used only by `sequence_runner.py` and two scripts.
- **`scoring.py` (368 loc)** — pure, deterministic idea judging. `applicable_coverage_fraction()` computes what share of the audience an idea's precondition addresses, unknown = `None` never 0 (scoring.py:15-46). `is_suppressed()` is the single benching rule: org mode → only `grounding_block_kind == "ungrounded"`; segment mode → hard block kinds `{concentration, per_pro_data}` or known coverage below 0.5; `framing` is a note, never a block (scoring.py:54-89). `ranked_ideas()` is the one canonical sort key (scored > suppressed > screening tie-break > llm-grounded > score…, scoring.py:135-167) shared by the scorer class, view model, analytics, and export winner_select. `support_tier_for_idea()` maps estimates to `unsupported/provisional/supported`, with a directional-prior carve-out (scored ⇒ supported) and a confirm-panel downgrade-only override (scoring.py:175-221). `score_generated_ideas()` sets `churn_risk_reduction_pp = persona_reduction_pp` or 0.0 (scoring.py:229-269). `enrich_winner_reasoning()` assembles a long prose rationale with mandated substrings ("LLM estimate … · health …", "Why it might not be good", 1-3 sample org UUIDs) (scoring.py:272-340).
- **`search_policy.py` (282 loc)** — `build_search_directive()` computes the next Karpathy-style research move from loop history: phases `baseline` → `screening_gradient` (build on positive screening leaders, avoid laggards — sign-disciplined so a negative estimate is never dressed up as a leader, search_policy.py:29-67, 195-222) → `normal`/`escape` (2 consecutive discards force `new_direction`) / `reassess` / `confirm` (budget ≤ 3 → only `reconfirm_champion`) (search_policy.py:80-118). `must_avoid` carries all prior titles. The directive is prompt-enforced by the generator with a retry-on-miss loop (generator.py:597-603, 897-898).
- **`opportunity_map.py` (57 loc)** — summarizes audience factor axes (value counts, coverage, example UUIDs) for the directive's `opportunity_axis` (opportunity_map.py:11-57).
- **`breadth_critic.py` / `grounding_critic.py` (202/196 loc)** — one Anthropic tool-call per idea batch, forced tool choice, temperature 0. Breadth classifies `none/framing/concentration/per_pro_data` for segment mode; grounding classifies `none/generic/ungrounded` against the org context pack for org mode. Both degrade to neutral (fields stay `None`) on **any** failure (breadth_critic.py:184-185, grounding_critic.py:179-180); both record token usage before parsing the tool result (breadth_critic.py:170, grounding_critic.py:165).
- **`calibration_priors.py` (69 loc)** — fail-open loader for `data/v1l/frozen/segment_action_priors.json` (per-segment measured action-type receptiveness + real 3-month churn), passed to the generator as guidance (runner.py:1143-1144). Artifact exists (data/v1l/frozen/, dated Jul 29).
- **`llm_usage.py` (232 loc)** — ContextVar-scoped per-run token/cost ledger. `usage_scope()` opened by the runner (runner.py:944-947); `record_response()` called by generator, both critics, the local reaction walk (local_reaction_runner.py:24, 139) and the OpenAI Doubt-Gap scorer (reaction_scorer.py:26, 223). Prices per MTok hardcoded and **verified accurate against Anthropic's published 2026-08 pricing** (llm_usage.py:32-41; fable-5 10/50, opus-5 5/25, sonnet-4-6 3/15, haiku-4-5 1/5; cache read 0.10x, write 1.25x match published multipliers). `totals()` returns `llm_cost_usd = None` when any model is unpriced or any call unmeasured — refuses to show a lying partial total (llm_usage.py:162-194).
- **`secret_scrub.py` (66 loc)** — value-based redaction: replaces the actual values of env vars whose names contain SECRET/TOKEN/PASSWORD/CREDENTIAL/PRIVATE_KEY/KEY/SNOWFLAKE_ with `***`, longest-first; caller-supplied secrets always scrubbed, env-discovered ones only at length ≥ 8 (secret_scrub.py:25-66).
- **`title_hygiene.py` (30 loc)** — two regexes that strip the literal internal-audience phrases "low usage max plan" / "max plan" / "low usage" from the front of titles (title_hygiene.py:5-30). Used by generator.py:23 and live_view.py:23.

## 4. Concern findings

**C2 (how are reactions tied to churn; churn risk overinflated) — diagnose.**
FOR: the live cards path's reaction→churn magnitude is *asserted, not learned*: `_validate_cards_direction` explicitly ACCEPTS a `slope_sign_forced_negative` artifact as "the expected, current state of the shipped cards calibration" (persona_response.py:541-556), and any `sign_forced` result is tagged `calibration_confidence="directional_prior"` (persona_response.py:506). Yet the UI-facing numbers are pp magnitudes from that untrusted transform (`reduction`, `screening_reduction_pp`), and `support_tier_for_idea` labels every scored directional-prior idea `"supported"` (scoring.py:207-211) — so an operator sees confident pp figures whose magnitude the system itself refuses to trust. That is a plausible root cause for "churn risk seems overinflated." Scale mismatch compounds it: the run goal defaults to **11.0pp** (models.py:487) while the code's own live-probe comment records per-channel reaction deltas of ~0.1-0.5pp (persona_response.py:188-190) and the significance floor is 1.0pp = p25 of measured per-cell effects (persona_gate.py:24-48).
AGAINST: decisions never rest on the inflated magnitude — `clears_goal` on the directional path gates purely on direction significance (`direction_ci_lower > 1.0pp`, persona_response.py:174-175), out-of-calibration estimates can never clear (persona_response.py:178-179), and failures/abstentions are fail-closed to `reduction=None` (persona_response.py:404-487).

**C4 (persona reactions vs actual churn had no correlation) — diagnose.**
FOR (consistent with the concern): the shipped cards calibration does not carry a learned reaction→churn slope — sign is forced negative (persona_response.py:552-556), and persona_gate.py:38-46 documents that the earlier 2.9pp floor was inflated by a level-offset bug (a single pivot "silently absorbed the level offset as if it were reaction-driven effect"). This unit's code is *built around the assumption that the correlation is not yet demonstrated* — the entire directional-prior/significance-gate regime exists because magnitude validation failed.
AGAINST/limits: whether reactions correlate with historical churn is decided by the fit artifacts and scripts (U11a `fit_cards_churn_calibration.py`, `data/v1l/results/phase2_fit_report_v2.json`) — not verifiable from this unit; see Unverified.

**C5 (scoring logic questionable) — diagnose.**
FOR: (a) `score_generated_ideas` collapses every non-scored idea to `churn_risk_reduction_pp = 0.0` (scoring.py:255-261), so an idea whose panel screened at −3pp and one that failed transport both score 0.0 — only the ranking tie-break (`_screening_sort_value`, scoring.py:116-132) distinguishes them, and only among unscored ideas. (b) `support_tier_for_idea` ignores `in_calibrated_range` for directional-prior ideas (scoring.py:207-211); today OOD can only arise from `CalibrationGate`/`RegionAwareGate` (persona_gate.py:71-79, 121-141 — the sequence-react path), so no live bug, but the coupling is latent: a sign-forced sequence-react artifact would let an out-of-distribution idea read "supported". (c) `settle_channel_by_scorer` switches to the best-scored alternate whenever the incumbent is unscored, even if that alternate's reduction is negative (persona_response.py:229-231), and its 0.25pp switch margin sits inside the 0.1-0.5pp noise band the comment itself cites (persona_response.py:188-191).
AGAINST: the ranking key is deterministic, single-sourced, and shared so scorer/view/export can never diverge (scoring.py:145-149); suppression semantics (unknown-neutral coverage, framing-is-a-note) are deliberate and documented (scoring.py:49-89); fail-closed discipline is consistent throughout persona_response.

**C6 (50-at-once; what else speeds it up) — diagnose.**
FOR: within one run, persona scoring is strictly serial — one `scorer.estimate()` per idea inside the loop (runner.py:1207); the machinery for concurrency exists but is dead (`estimate_many` ThreadPool(10), persona_response.py:877; no production caller). The advertised request-dedupe also does not exist on the live HTTP path: `PersonaResponseScorer`'s docstring claims "identical react requests … hit the backing transport exactly once" (persona_response.py:785-789), but `_wrap_evaluator_with_memo` no-ops for both real clients (persona_response.py:746-752; local_reaction_client.py:26). Note: even if `estimate_many` were used, its ContextVar usage ledger would not propagate into worker threads (llm_usage.py:197-199; threads don't inherit ContextVar values), silently dropping cost data — concurrency here needs a design pass, not a flag flip.
AGAINST/mitigations already present: the cards path memoizes identical panels+sequences in `LocalReactionClient._memo` (local_reaction_client.py:31-45) and fetches at Riley's 24-persona floor but **walks only the requested 3** (local_reaction_client.py:23, 50-56) — the expensive LLM walk is already minimized. Non-parallel speedups available: score the round's batch concurrently (the seam exists), cache the prefix-only request per run, drop the winner run-off's 2 extra calls when the margin can't change the decision.

**C7 (expensive; can't swap model; inaccurate cost reporting) — diagnose.**
FOR (model swap): the reaction-walk model — the highest-volume LLM call (panel × ideas × steps) — is hardcoded: `LocalReactionRunner()` built with no model arg (persona_response.py:646), defaulting to `DEFAULT_MODEL = "claude-sonnet-4-6"` (llm_tooling.py:19, local_reaction_runner.py:117); the Doubt-Gap scorer is hardcoded `gpt-4o-mini` (reaction_scorer.py:28). Only the generator/critics read `PATHFINDER_ACTION_CONSOLE_LLM_MODEL` (breadth_critic.py:157, grounding_critic.py:152).
FOR (cost reporting, one concrete bug-shaped gap): `gpt-4o-mini` is not in `PRICES_USD_PER_MTOK` (llm_usage.py:32-41), and `totals()` returns `llm_cost_usd=None` whenever any model is unpriced (llm_usage.py:188-190) — so **every cards-path run that scores reactions shows no dollar cost at all** (honest, but reads as "cost reporting broken"). One price-table line fixes it.
AGAINST: the ledger itself is sound and current — Anthropic prices verified correct against published 2026-08 rates including cache multipliers (llm_usage.py:32-48); it records generator, critics, reaction walk, and scorer (local_reaction_runner.py:139, reaction_scorer.py:223); it refuses to fabricate partial totals and names the unpriced models (`llm_unpriced_models`, llm_usage.py:191).

**C8 (seed overly crucial; want fresh ideas AND exploitation) — diagnose.**
FOR (exploration+exploitation exists in code): `screening_gradient` explicitly builds on positive leaders and avoids laggards' mechanisms (search_policy.py:29-67); stall of 2 consecutive discards forces a single `new_direction` escape (search_policy.py:96-99); `must_avoid.titles` accumulates all prior titles (search_policy.py:59, 234-239); rejected directive misses push `problem_key`/`mechanism_key` into `must_avoid` (generator.py:1014-1030).
AGAINST (why micro-improvement behavior can still occur): branch advancement is a pure greedy hill-climb — `keep` only when `idea.score() > current_branch.score()` (runner.py:555-566), and in `normal` phase all four moves are allowed with the choice delegated to the LLM by prompt text only (search_policy.py:100-106, generator.py:599-603). Nothing structurally forces a fresh direction each round when the branch isn't stalled; enforcement is prompt+retry, not schema.

**C10 (is it actually the Karpathy method?) — code-level verdict: a real but simplified Karpathy loop.**
FOR: keep/discard/crash branch semantics with before/after branch snapshots (`_apply_autoresearch_result`, runner.py:504-580: crash resets to prior keep; suppressed can never advance; improvement advances the branch); a compact experiment ledger (`_results_log_row` with research_move/hypothesis/status, runner.py:473-501) fed back into every generation round (`_idea_generation_memory`, runner.py:583-609, last-12 window); phased research directives with budget awareness (search_policy.py:80-118); directive-miss retry (generator.py:897-898, 988-989).
AGAINST/limits: the "evaluation" is a single scalar (`score()`), advancement is strictly greedy, there is no branch-per-candidate/reset mechanics in this unit (that lives in the older runner/plan machinery), and move discipline is prompt-enforced, not mechanical. Verdict: Karpathy-*style* autoresearch, genuinely implemented at the loop level; not the full branch-per-candidate method.

**C11 (loop decides its own ceiling) — design.**
Current support: the loop self-terminates on `search_exhausted` after 3 consecutive directive-exhausted rounds (runner.py:1136-1171, 1302-1303), enters a forced `confirm` phase when `remaining_budget <= 3` or goal reached (search_policy.py:81-84), and stops on a confirmed goal clear (runner.py:1257-1291). Blockers: the ceilings themselves (`max_ideas`, `persona_call_budget=80`, models.py:487-489) are fixed config/env, not loop-chosen. New-repo decision: keep the hard cap, let the directive layer emit a stop recommendation (it already has the ledger to justify one).

**C14 (lots of env vars / long names) — design.**
FOR: this unit alone reads **17 env vars**, including `PATHFINDER_ACTION_CONSOLE_PERSONA_MODEL_KEY`, `PATHFINDER_PERSONA_SERVICE_429_RETRY_DELAY_S`, `PATHFINDER_ACTION_CONSOLE_REQUIRE_FROZEN_SUBTYPE`, `PATHFINDER_PERSONA_CARDS_SNAPSHOT`, plus two aliases for the same timeout (`PATHFINDER_PERSONA_SERVICE_TIMEOUT` falling back to `PATHFINDER_ACTION_CONSOLE_PERSONA_TIMEOUT_S`, persona_response.py:690-695). All in persona_response.py:537-710, breadth_critic.py:147-157, grounding_critic.py:142-152. New-repo decision: one typed settings object, one prefix, no per-knob aliases.

**C16 (long unstructured output) — design.**
FOR: `enrich_winner_reasoning` produces a single prose blob with contract-mandated substrings and embedded UUID samples (scoring.py:288-321); estimate `explanation` packs numbers into strings ("synthetic_persona_v1l: churn reduction …", persona_response.py:518-521). AGAINST: nearly everything else in this unit is structured fields (screening values, tiers, block kinds, directive dicts) — the wall-of-text problem here is localized to the winner rationale.

**C17 (use actual message copy) — design.**
FOR the gap: personas never see copy — they react to a scrubbed *concept* ("Action concept for the pro: …", persona_response.py:276-309), and the scrubber actively rewrites operational detail out (persona_response.py:254-273). Nothing in the scoring path generates or evaluates real message text. New-repo decision: score the actual draft copy (or at least pass the pro-facing concept verbatim) once a copy source exists; the seam is `_persona_strategy_content`.

**C18 (is churn-risk testing present in the output?) — diagnose: yes.**
Every idea carries persona status/reduction/CI/n into the run record and Supabase rows (`_attach_persona_fields` runner.py:386; `_action_idea_row` runner.py:638-640 including `screening_reduction_pp` and `confirmation_status`); the compact results ledger includes screening values so abstained rows aren't flat zeros (runner.py:496-500); the winner carries a per-persona `final_choice_panel` readout (persona_response.py:982-1009, runner.py:1358-1367). Presence confirmed; the *trustworthiness* of the numbers is the C2/C4 issue above.

**C3 (individual-pro / custom persona) — design.**
Current code blocks it: panels are keyed by segment only — `segment_code_to_persona_key(cell or audience.label)` (persona_response.py:323-333, segment_vocab.py:11-17); org-by-org mode reuses the same segment-persona scoring (runner passes the org-mode audience through the same `scorer.estimate`); no per-org persona anywhere in the scoring path. The cards service also enforces a 24-persona panel floor (local_reaction_client.py:23), so "one persona = this pro" needs Riley-side support or a local card synthesized from the org context pack. New-repo decision: the seam to extend is `_build_candidate` + `PersonaCardsClient.fetch_panel` — an org-mode branch that builds a persona card from the org context pack would slot in without touching the calibration stack.

**C19 (past runs feed future decisions) — design.**
In this unit, memory is within-run only (`_idea_generation_memory` sees this run's evaluated ideas, runner.py:583-609). Cross-run: branch-a-run exists — a child run loads the parent run's ideas as context and records `parent_run_id` (runner.py:1582-1650) — but nothing feeds a *corpus* of past runs into `build_search_directive`. Blocker is data shape, not architecture: the directive builder takes `evaluated_ideas: list[GeneratedIdea]` and would accept prior-run winners today.

**C1, C9, C12, C13, C15, C20, C21** — not evidenced in this unit's files. C9 (Amplitude): zero references anywhere in `src/` or `scripts/` (grep, 2026-08-05) — pure greenfield. C15 (Supabase): this unit performs no Supabase reads; the runner's Supabase *writes* are U9a/U10x territory. **NOVEL findings:**

## 7. Gaps

1. **Silent critic failure disables the only org-mode gate.** Both critics degrade to neutral on *any* exception — including missing `ANTHROPIC_API_KEY`, auth failure, or timeout (breadth_critic.py:147-149, 184-185; grounding_critic.py:142-144, 179-180; timeout 90s, `max_retries=0`). Nothing is logged or surfaced on the run. In org mode `grounding_block_kind == "ungrounded"` is the *sole* suppression rule (scoring.py:70-75), so a misconfigured key means every fabrication-risk idea passes unbenched with no operator-visible signal. Minimum fix: count and surface `critic_error` on the run record.
2. **Directional-prior "supported" bypass of `in_calibrated_range`** (scoring.py:207-211) — safe under today's gate pairing, but nothing enforces the pairing; documented as latent coupling under C5.
3. **Channel run-off can pick a negative-scoring channel** when the incumbent estimate failed (persona_response.py:229-231); no floor check on the alternate.
4. **`gpt-4o-mini` unpriced** → every cards run's `llm_cost_usd` is `None` (llm_usage.py:32-41, 188-190).
5. **Secret scrubbing is exact-value only** — an encoded (base64/URL-escaped) secret in a driver error passes through (secret_scrub.py:57-66); acceptable for the stated threat model, worth noting.
6. **`_resolve_snapshot_path` anchors on `CARDS_CALIBRATION_PATH.parents[3]`** (persona_response.py:559-566) — correct today, but the repo-root computation is duplicated in three modules (persona_response.py:65-68, calibration_priors.py:21) and silently breaks if the file moves depth.
