# U10x — export/store/adapters: sheets, post_api, contacts, winner_select, cli, supabase_sink, delivery_adapter

Auditor: unit-audit agent (Liann's primed run). Read-only; all 11 manifest files read in full.

## 1. What it actually does

This unit is the **tail end of the north-star path**: after the action-console loop finishes, it turns Supabase run rows into "one winning theme per org", joins contact emails, and hands the result to the LCM tool via Google Sheet and/or POST. Plus the general Supabase run-mirror client, plus a Phase-1 "delivery adapter" that can only refuse.

- **`src/pathfinder/store/supabase_sink.py`** — a zero-dependency (stdlib `urllib`) PostgREST client. Writes are best-effort upserts that swallow every error and return a bool (`_upsert`, supabase_sink.py:425-441); reads return `None` on any failure (`_get_list`, supabase_sink.py:396-412). Serves two generations of tables: legacy strategy runs (`Pathfinder_runs`/`Pathfinder_experiments`, supabase_sink.py:33-34, used by `src/pathfinder/runner.py:633,1174,1316` and `viewer/reader.py:504`) and the current action-console tables (runs, ideas, org-uuid evidence, branch signals, audience index; supabase_sink.py:36-40). Also hosts the **audience index**: org attribute rows (plan, usage bands, AR bands…) upserted in batches then stale-swept by `refresh_id` (`replace_action_audience_index`, supabase_sink.py:296-374) and queried with a column-allowlisted filter DSL (`_audience_filter_query`, supabase_sink.py:378-394).
- **`src/pathfinder/export/winner_select.py`** — for each run id: fetch the run row + idea rows from Supabase, require `status == "completed"` and exactly one org in `audience.org_uuid_evidence` (winner_select.py:74-79), drop suppressed / non-"supported" ideas using the console's own canonical scoring (`is_suppressed`, `support_tier_for_idea`, `ranked_ideas` imported from `action_console.scoring`, winner_select.py:14-18, 57-66), and emit `WinnerRow(theme, theme_category, third_theme, …)`. First and **third** ranked ideas are captured (winner_select.py:86); second is deliberately skipped (design doc claims "test-plan decision: logged as free columns, not sent", docs/superpowers/specs/2026-07-28-batch-winner-sheet-export-design.md:53-57 — code matches).
- **`src/pathfinder/export/contacts.py`** — loads a contacts CSV keyed on `org_uuid` (preferred) or `org_id` (contacts.py:29-34), first-row-wins on duplicates with a warning (contacts.py:49-54), and lays out the fixed 12-column sheet row (`SHEET_COLUMNS`, contacts.py:13-17). `approved` and `message` start blank — the sheet is a review surface and the LCM tool writes the copy (contacts.py:2-5, 81-82). Ready winners without a contact become `missing_contact` (contacts.py:67-71).
- **`src/pathfinder/export/sheets.py`** — 88-line Google Sheets v4 client: list tab titles, add tab, PUT values; `export_tab` refuses to overwrite an existing tab (`TabExistsError`, sheets.py:75-81 — append-only paper trail). Auth is an optional `google-auth` service account deferred into the default transport (sheets.py:27-44; declared as extras group `sheets`, pyproject.toml:22). Also `write_csv` (sheets.py:84-88).
- **`src/pathfinder/export/post_api.py`** — POSTs `{"batch": label, "rows":[{row_id,email,theme,theme_category,pro_name,org_id}]}` to the LCM intake endpoint with Bearer token + `x-vercel-protection-bypass` header (post_api.py:145-153). Rows missing email or theme are skipped (post_api.py:104-107); `row_id` = run_id so retries dedup server-side (docstring claim, post_api.py:6-9). Internal `idea_category` values are keyword-mapped onto Allison's 8-value enum, unmatched → `"other"` (post_api.py:58-85). Retries 5xx/network up to 2 times; 4xx codes map to human hints (post_api.py:37-44, 185-206). Client-side 500-row cap (post_api.py:28, 209-214). `batch_status` GETs per-batch generated/skipped/failed counts (post_api.py:222-225).
- **`src/pathfinder/export/cli.py`** — the orchestrator behind `scripts/export_batch_winners.py`. Parses run ids (inline or file), hard-requires a configured Supabase sink (cli.py:128-131, exit 2), selects winners, joins contacts, then writes CSV and/or a new Sheet tab and/or POSTs to LCM; any Sheet/POST failure falls back to a CSV (`winners_fallback.csv`) with the error printed (cli.py:148-153, 160-161, 183-184). Reads secrets from process env then a hand-parsed `.env.local` (hyphenated header-style keys can't be shell-exported — cli.py:23-36), with per-secret name aliases and a case-insensitive pass (cli.py:39-52). POST receipts are persisted to `<csv>.receipts.json` only when `--csv-out` was given (cli.py:176-182).
- **`src/pathfinder/adapters/delivery_adapter.py`** — a send gate whose every branch raises `DeliveryBlocked` (delivery_adapter.py:54-73): kill switch → dry-run CSM gate that still refuses (`DRY_RUN_NO_SEND`) → `REAL_SEND_DISABLED` → `PHASE2_NOT_SIGNED`. There is no code path that sends anything. Its only production caller is the **legacy** Phase-1 strategy runner, which invokes it as an in-loop containment self-check and treats a non-raise as an invariant violation (src/pathfinder/runner.py:574, 877-889). The current action-console → export path never touches it.
- **`store/__init__.py`** re-exports `SupabaseSink` (store/__init__.py:10-12); `adapters/__init__.py` is a 2-line docstring; `export/__init__.py` and `adapters/.gitkeep` are empty.

## 3. Ponytail findings (biggest cut first)

1. **delete:** `adapters/` package (~75 lines + tests/test_delivery_adapter.py + tests/test_delivery_dry_run.py) — a class that can only raise, called only by the legacy runner to prove it raises (src/pathfinder/runner.py:877-889); in a rebuild the invariant is achieved by absence.
2. **shrink:** supabase_sink.py 487→~150 lines for the north-star: export needs only `get_action_run` + `list_action_generated_ideas` + `_get_list`/`_upsert`; audience-index methods (supabase_sink.py:247-394) move to Snowflake/n8n per C15, legacy runs/experiments methods (119-125, 163-170) go with the legacy runner.
3. **shrink:** three hand-rolled urllib JSON transports in one unit (sheets.py:27-44, post_api.py:156-166, supabase_sink.py:396-473) — one ~15-line `_json_request(method, url, payload, headers, timeout)` helper serves all three.
4. **yagni:** `LcmClient.post_rows` (post_api.py:217-220) — no production caller (cli.py:167-170 composes the two halves itself); only its own tests use it (tests/test_export_post_api.py:112-165).
5. **shrink:** secret aliasing in cli.py (`_secret` two names per secret + case-insensitive pass, cli.py:39-52) — one canonical env name per secret deletes ~20 lines and is direct C14 relief.
6. **yagni:** backslash/quote escaping of run ids in `list_action_generated_ideas_bulk` (supabase_sink.py:215-223) — run ids are self-generated timestamps, not adversarial input.
7. **delete:** `adapters/.gitkeep` — directory is not empty.

## 4. Concern findings

- **C15 (Supabase transition) — FOR, strongest in this unit.** The export leg has no non-Supabase path: cli.py exits 2 when the sink is unconfigured (cli.py:128-131) and `select_winners` reads run + idea rows exclusively from Supabase (winner_select.py:99-105). The audience index — org attributes like plan/usage/AR bands — is stored and queried in Supabase (supabase_sink.py:36-65, 247-294) and refreshed via batch upsert + stale sweep (296-374). **AGAINST:** for *run history* Supabase is explicitly a best-effort mirror with local files as truth (store/__init__.py:1-8, supabase_sink.py:2-14); the run-mirror use is not the org-data pull C15 targets. New-repo decision: keep a small run store (any DB), source audience/org attributes from Snowflake/n8n directly, and give the exporter a local-artifact fallback so it does not hard-require the mirror.
- **NOVEL (silent listing failure).** `list_action_runs` selects the full `audience` column (supabase_sink.py:66-80 incl. line 74) with `limit=200` default under `_TIMEOUT_S = 4.0` (supabase_sink.py:82,169-176), and `_get_list` converts any timeout into `None` (408-412). `audience` carries the whole `org_uuid_evidence` blob (winner_select.py:38-46 parses it), so run listing scales with audience size and can silently degrade the dashboard to local-only (`live_view.py:408-441` falls back without surfacing an error). A projection like `audience->filters` for listing (full blob only in single-run `get_action_run`) fixes it; not present in current code (`grep "audience->"` → no hits in src/). Prior-session measurement of 74MB/13s is Unverified (§8).
- **NOVEL (missing vs unavailable conflated → wrong export status).** `get_action_run` returns `None` for both "row absent" and "Supabase unreachable" (supabase_sink.py:178-186), and winner_select maps `None` to `RUN_FAILED` (winner_select.py:74-75). A transient 4s timeout mislabels a completed run as `run_failed` in the sheet handed to humans. The sink documents the `None`-vs-`[]` distinction for lists (supabase_sink.py:164-168) but single-row reads erase it.
- **NOVEL (receipts not durably persisted).** The comment admits rejected rows "are silently dropped on her side" and the receipt is "the record" (cli.py:177-178), yet the receipt JSON is written only when `--csv-out` was passed (cli.py:176-182); a Sheet-or-POST-only invocation leaves the only record of rejected rows in stdout.
- **NOVEL (audience swap not atomic; delete under 4s timeout).** `replace_action_audience_index` upserts all batches, then two DELETEs sweep stale rows (supabase_sink.py:347-356); readers can see mixed refreshes mid-swap, and `_delete` runs under the 4s `_TIMEOUT_S` (475-487) — a large stale sweep timing out reports "did not fully persist" (358-363) even though all upserts succeeded.
- **C14 (env vars / long names) — FOR.** `PATHFINDER_ACTION_CONSOLE_SUPABASE_WRITE_TIMEOUT_SECONDS` (52 chars, supabase_sink.py:83-85), `PATHFINDER_ACTION_CONSOLE_SUPABASE_AUDIENCE_PAGE_SIZE` (86), `PATHFINDER_ACTION_CONSOLE_SUPABASE_AUDIENCE_LIMIT` (260-265); three accepted names for the Supabase key (supabase_sink.py:104-110); two names each for the LCM token and Vercel bypass (cli.py:92-95); `PATHFINDER_WINNERS_SHEET_ID`, `PATHFINDER_LCM_POST_URL` (cli.py:75, 81). **AGAINST:** each var has a default and the aliases exist because a real header key (`x-vercel-protection-bypass`) is not shell-exportable (cli.py:24-26). New-repo decision: one canonical name per secret, a single config object, and per-call timeouts as function args not env vars.
- **C16 (long unstructured output) — AGAINST (counter-example).** This unit already reduces a whole run to one theme + category + third theme in a fixed 12-column row (contacts.py:13-17, winner_select.py:87-96). The wall-of-text problem lives upstream; the export proves the compact shape exists and works.
- **C17 (actual message copy) — FOR the gap being real, by design.** The export deliberately ships a *theme*, not copy: `message` starts blank for the LCM tool to fill (contacts.py:2-5, 82) and the confirmed LCM contract is theme-based (post_api.py:1-16). New-repo decision: shipping near-actual copy means renegotiating the intake contract or adding a copy field alongside `theme` — nothing in this unit blocks it, but nothing provides it.
- **C18 (churn-risk in output) — FOR.** No churn-risk number survives to the deliverable: `SHEET_COLUMNS` (contacts.py:13-17) and `LCM_ROW_FIELDS` (post_api.py:46) contain no expected_pp/confidence/tier field. Churn testing *gates* the winner (supported-tier filter, winner_select.py:57-65) but the magnitude is discarded at the boundary. One extra column would carry it.
- **C2 (churn risk overinflated) — weak FOR, in-code admission.** The winner filter's own comment states a screen-then-confirm idea that failed its confirm re-score "still carries its original, often inflated, search-panel score" (winner_select.py:60-63) — the codebase itself documents score inflation on the search panel; the supported-tier gate is the mitigation at this boundary.
- **C5 (scoring logic questionable) — AGAINST at this boundary.** The export re-uses the console's canonical `is_suppressed`/`ranked_ideas`/`support_tier_for_idea` rather than re-implementing (winner_select.py:14-18, 57, 82), so display and send apply identical verdicts; whatever is wrong with scoring is wrong in exactly one place (U-scoring), not forked here.
- **C1 (poor reporting) — mixed.** FOR: single-row `_upsert` swallows HTTP error bodies and returns a bare bool with zero logging (supabase_sink.py:438-441) — mirror write failures are invisible at the sink (the runner counts them separately, action_console/runner.py:1381 comment). AGAINST: the export CLI is a counter-example — every failure prints a reason and falls back to a durable CSV (cli.py:148-153, 160-161, 183-184), and `_upsert_many` returns the HTTP body as a message (supabase_sink.py:464-473).
- **C20 (file structure) — FOR.** Three top-level packages for one pipeline stage: `adapters/` holds one always-raising class, `store/` holds one client, `export/` holds the actual feature. A rebuild collapses this to `export/` (+ its store client), deleting `adapters/` entirely.
- **NOVEL (category fidelity dies at the keyword mapper).** `to_lcm_category` maps anything without a keyword hit to `"other"` (post_api.py:79-85), and the LCM side keys CTA/link selection off this category. The mapper is only as good as upstream `idea_category` values (a known mix of snake_case buckets and free-text LLM labels, post_api.py:54-57); fixing the "60% → other" problem is an upstream generator/category task, not a mapper bug — but this is the exact line where it lands.

## 7. Gaps

- **Trust boundary — Supabase read failures indistinguishable from empty**: `get_action_run` (supabase_sink.py:178-186) → export mislabels runs `run_failed` (winner_select.py:74-75); `list_action_audience_index` returns `[]` for an *invalid filter key* (supabase_sink.py:254-257 + 384-386) — a typo'd key silently yields zero orgs, same shape as "no matches".
- **Silent write failures**: `_upsert` discards the HTTP response/body entirely (supabase_sink.py:436-441); no logging module anywhere in the sink.
- **Listing payload vs timeout**: full `audience` column at limit=200 under 4s (supabase_sink.py:74,82,172-176) — silent `None`, dashboard quietly degrades (live_view.py:441).
- **Receipts durability conditional on `--csv-out`** (cli.py:176-182) despite the receipt being "the record" of server-side-dropped rows (cli.py:177-178).
- **Non-atomic audience swap** + stale DELETE under 4s timeout (supabase_sink.py:347-356, 475-487).
- **Error-type inconsistency in LcmClient**: HTTP errors become `LcmPostError`, but `URLError` after retry exhaustion re-raises raw (post_api.py:202-206); harmless today because cli catches `Exception` (cli.py:183).
- **`.env.local` resolved relative to cwd** (cli.py:23,86): running the exporter from another directory silently loses secrets and produces a 401/403 instead of a "missing secret" message.
- **Sheets `export_tab` check-then-create race** (sheets.py:75-81): two concurrent exports with the same tab pass `tab_titles()` before either `add_tab`; the Sheets API rejects the duplicate addSheet, so it surfaces as a generic error, not `TabExistsError`. Minor.
- Security: no secret is ever printed or logged in this unit; tokens travel only in headers (post_api.py:145-153, supabase_sink.py:414-423). No injection surface beyond URL-encoding, which is applied to run ids, tab titles, and filter values (supabase_sink.py:180,388-393; sheets.py:68; post_api.py:224).
